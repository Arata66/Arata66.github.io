# 博客工程维护方案

## 目标与范围

更新现有 GitHub 仓库 `Arata66/Arata66.github.io`，保留 Hexo、Butterfly 和当前视觉风格，为日后零散更新建立稳定的检查与构建流程。

本轮不发表近况文章，不推测作者未完成项目的进度，不上传 Azure 服务器。文章选题先整理为本地草稿清单。

## 方案比较

| 方案 | 工作内容 | 取舍 |
| --- | --- | --- |
| 基础维护（推荐） | 检查入口、锁文件、行为测试、自动构建、构建报错、文档同步 | 保留现有技术栈，便于验证和继续使用 |
| 完整运维升级 | 在基础维护上增加服务器原子发布、回滚、密钥配置迁移 | 需要核对服务器权限与目录，适合独立实施 |
| 更换框架 | 迁移页面、文章、组件和发布流程 | 成本较大，当前没有足够需求支持 |

## 具体变更

1. 质量检查：提供 `lint`、`typecheck`、`test`、`check` 命令。原生 JavaScript 保持现有写法，类型检查使用 TypeScript 检查 JavaScript，并明确覆盖范围和必要全局声明。
2. 依赖管理：将锁文件纳入版本控制，README 采用 `npm ci`，避免不同机器解析出不同依赖版本。本轮不做 Hexo 或 Butterfly 主版本升级。
3. 行为测试：使用 Node.js 测试运行器和 DOM 环境，验证手机工具展开、收起、无障碍状态以及 Pjax 重初始化。现有 CSS 规则检查作为补充，文档明确它不是视觉回归测试。
4. 构建可靠性：登记的 CSS/JS 文件缺失时构建失败，避免跳过后仍发布不完整页面；为该失败行为及正常资源合并编写测试。
5. 持续集成：GitHub Actions 在提交和拉取请求时依次安装固定依赖、运行质量检查并构建。工作流仅检查和构建，不访问 Azure 或使用服务器密钥。
6. 文档同步：新增根 README，修正当前命令、项目目录与历史计划状态；同步 AGENTS.md、CLAUDE.md 和项目记忆中与本轮变更有关的规则。
7. 内容准备：整理可以从局部经验写起的文章选题，区分能直接根据博客代码撰写的选题和需要作者补充真实经历的选题。

## GitHub 更新方式

先核对真实远端分支与本地历史；若有远端新增提交，先保留并整合。使用 `Arata66/blog-maintenance` 分支承载维护变更与本地尚未同步的移动端优化，检查完成后推送并建立拉取请求，保留审核入口。

禁止强制推送、覆盖远端历史和提交访问凭证。本轮不运行会清空服务器目录的 `deploy.sh`。

## 验收标准

- `npm ci` 能按锁文件恢复依赖。
- `npm run lint`、`npm run typecheck`、`npm test`、`npm run build` 全部成功。
- `git diff --check` 成功。
- 行为测试覆盖工具初始折叠、点击展开、工具操作后收起、滚动收起和桌面恢复。
- 必需合并资源缺失时明确失败，完整输入时正确输出。
- README 的安装、检查和预览命令与实际脚本一致。
- GitHub 上能查看维护分支、变更和拉取请求；远端检查结果单独报告，不把本地通过当成远端通过。
