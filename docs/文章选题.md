# 文章选题草稿

本文只保存选题，不会生成已发布文章。选题不要求项目完成，也不把学习中断包装成成果；涉及个人经历时，由作者决定写到什么程度。

## 可以直接从博客代码取材

### 1. 手机上的目录为什么挡住了正文

- 范围：一个文章页布局问题，不写完整建站教程。
- 材料：`docs/mobile-article-layout-plan.md`、`source/js/mobile-rightside.js`、`source/css/custom.css`。
- 提纲：手机上原先的遮挡现象 → 固定浮层与流式目录的区别 → 工具栏折叠和安全区 → 仍需真实手机验证的地方。
- 写作边界：代码由工具协助修改时，可以直接说明，不必写成作者独立完成全部排错。
- 可补材料：一组手机截图。没有旧截图时，使用布局示意并标注示意，不伪造故障截图。

### 2. Hexo 预览时，为什么有些自定义样式没出现

- 范围：本项目的资源合并流程。
- 材料：`package.json`、`scripts/merge-assets.js`、`scripts/cache-bust.js`、`_config.butterfly.yml`。
- 提纲：源文件与合并包的关系 → server 与 build 的区别 → 新文件需要登记 → 更新后如何避免旧缓存。
- 写作边界：明确是本项目定制流程，不把所有 Hexo 项目概括成同样行为。

### 3. 我给博客做了一个能拖动的音乐球

- 范围：播放器交互与取舍。
- 材料：`source/js/music-ball.js`、`source/css/music-ball.css`、已有 Git 记录。
- 提纲：悬浮入口与面板 → 拖动、音量和位置保存 → 触摸操作 → 外部歌单服务失败时的表现。
- 写作边界：不承诺所有歌曲都能完整播放；历史上的试听限制写成服务边界，不写未经验证的解决办法。

### 4. 隔了几个月，再打开自己的博客项目

- 范围：项目恢复操作记录，不要求公开生活近况。
- 材料：Git 记录、现有维护方案、实际执行过的检查结果。
- 提纲：先找到源码目录 → 核对本地与远端差异 → 恢复依赖并构建 → 修正文档和补检查入口。
- 写作边界：只记录本轮实际发生的事，可以完全不谈暑假和学习进度。

## 需要补充真实经历后再写

### 5. 学 MC Mod 时，我先弄清楚了哪几个名字

- 适用条件：作者确实接触过这些概念，并愿意整理自己的理解。
- 可选范围：Minecraft、加载器、开发工具、Java 与游戏版本的关系；仅选实际接触的一两项。
- 所需材料：正在使用的版本、加载器、教程和一个具体困惑。
- 写作边界：未确认版本前不生成安装步骤；理解仍不确定时标为学习笔记，并核对官方文档。

### 6. 一个没做完的小项目，目前停在哪里

- 适用条件：作者愿意写；没有义务公开中断原因。
- 可选对象：OtakuLog Lite。
- 提纲：原本想解决的问题 → 已经能运行的最小链路 → 当前卡住或中断的位置 → 只写一个下一步。
- 所需材料：目标项目的真实代码与运行结果。
- 写作边界：博客里的 OtakuLog 与后续学习用的 OtakuLog Lite 是不同项目，不能混用功能和完成度。

## 最容易开始的一篇

优先选择“Hexo 预览时，为什么有些自定义样式没出现”：材料已经在仓库里，一个问题足够写成短文，也无需先补完其他项目。

若希望更像日常随手记录，可以选择“隔了几个月，再打开自己的博客项目”，只写本轮恢复与维护过程。
